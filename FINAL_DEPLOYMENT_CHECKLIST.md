# Final staging and live release checklist

**READY FOR STAGING — NOT APPROVED FOR LIVE.** No deployment is authorized by this document.

1. **Isolation:** The confirmed V5 design has six choices, three nuclear and three oil-fired. Use a separate Final app and new PostgreSQL database, credentials and backups. Keep V5 and previously created Final sessions on their existing runtimes/databases; create corrected-flow sessions in an isolated environment and do not migrate existing participants. Both prior and corrected Final exports use `survey_version=final`; distinguish sessions using `session_code` and their recorded `app_sequence`, and do not combine data from different survey orders. Never reset or migrate V5 as part of this release.
2. **Environment:** Python 3.11, `pip install -r requirements.txt`, stable high-entropy `OTREE_SECRET_KEY`, `OTREE_ADMIN_PASSWORD`, `OTREE_PRODUCTION=1` and isolated PostgreSQL `DATABASE_URL`; review pinned oTree and actual Heroku configuration. Never record secrets in logs. Verify TLS, access, provider processing, retention, backup and restoration. Dyno filesystem is ephemeral.
3. **PostgreSQL staging test:** Create a disposable, **empty**, isolated PostgreSQL database whose database name starts `final_test_`; never point the test at a study DB. Install `requirements-dev.txt`, set `FINAL_TEST_DATABASE_URL` securely, then run `python scripts/postgres_qa.py --confirm-disposable-empty-db`. This creates oTree tables and synthetic production-labeled records in that test database; it must never be used for real data. Review the output, simulate simultaneous conflicting posts for one participant, and independently rehearse deletion with `FINAL_DATA_DELETION_GUIDE.md`. The script has not been executed against PostgreSQL.
4. **Browser and devices:** Chrome emulated 320–1280 px passed locally. Check real iOS/Android devices, native country menu, soft keyboard, screen readers, and target browser behavior. Review technology logo permissions and neutral presentation. QA results and 375 px synthetic screenshots are in `FINAL_TEST_REPORT.md` and `test_artifacts/browser/`.
5. **Deletion and privacy:** Follow `FINAL_DATA_DELETION_GUIDE.md`. Validate full worker shutdown and page-time buffer handling for the intended dyno count; test PostgreSQL transactional deletion on a disposable restored database; inventory logs, exports and backup copies and agree on retention and restoration policy. Review the consent text, timing, optional free text, recipients and processors. Until this is operational, do not invite real respondents.
6. **QA session:** Confirm the order is Eligibility / Consent → six Housing Choices → Attitudes → Household / Optional Feedback → Completion. In an isolated staging app, create `survey_final_qa` for at least 20 synthetic participants. Its `qa`/`synthetic` records are excluded from the production export. Verify journey, assignment, dropout, export, restart, and timing choices. Verify simultaneous export and same-participant replay on the actual database. Test multi-dyno only if multiple dynos will actually be used.
7. **Production session:** After all release checks and explicit deployment authorization, create a fresh `survey_final_production` (`live`/`production`) session with adequate capacity. No room is preconfigured; use generated start links or explicitly configure a room and test it. Protect participant URLs and references.
8. **Export:** Download `household.custom_export` for completed production records and `household.custom_export_timing` for consenting completed records. Native oTree exports and the old V2.4 exporter contain operational/historical data and are not Final research exports. Store protected snapshots and track copies for deletion.
9. **Cleanup and rollback:** No automatic stale-participant cleanup is provided. Approve a concurrency-safe retention process before implementing one. Stop routing new participants to Final if rolling back, preserve its database and protected backup, and route to the untouched V5 deployment where appropriate. Do not reverse-migrate or point Final at the V5 database.
