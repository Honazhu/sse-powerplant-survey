# Heroku readiness

**NOT VERIFIED for deployment.** Heroku CLI was not found; app existence, region, stack, database, dynos, configuration, costs and GitHub integration were not inspected. The intended region is EU only if actual metadata confirms it. No resource was created.

- Python: `.python-version` requests `3.11`, matching the locally tested major version. Heroku's classic Python buildpack v359 reports 3.11.18 as the alias on 2026-10-26; actual chosen patch/stack must be confirmed from the build log. Local macOS is 3.11.17. Heroku marks 3.11 deprecated and new apps default to 3.15; plan a separately tested future upgrade. Sources: [runtime selection](https://devcenter.heroku.com/articles/python-runtimes), [support policy](https://devcenter.heroku.com/articles/python-support), [buildpack releases](https://github.com/heroku/heroku-buildpack-python/releases).
- oTree: exactly 6.0.15. `Procfile` declares `web: otree prodserver1of2`. Installed 6.0.15 source starts its timeout subprocess inside web; `prodserver2of2` is a legacy idle loop. Local SQLite production-command startup returned HTTP 200 with a disposable database and was stopped. A separate worker is therefore not indicated by this installed version, despite the [upstream example Procfile](https://github.com/oTree-org/oTree/blob/lite/Procfile); verify actual hosted startup. One web dyno and a persistent Postgres add-on incur charges based on the plans selected; prices, billing, quota and sizing require researcher review. oTree recommends no more than one web dyno. See [oTree Heroku](https://otree.readthedocs.io/en/latest/server/heroku.html), [server setup](https://otree.readthedocs.io/en/latest/server/intro.html), [Heroku Procfile](https://devcenter.heroku.com/articles/procfile), [Postgres plans](https://devcenter.heroku.com/articles/heroku-postgres-plans). Do not add an automatic `resetdb` or migration release phase.
- Dependencies: current production requirement is `otree==6.0.15`, with its own pinned transitive dependencies; analysis tools additionally require the development requirements, including pandas. A PostgreSQL driver is absent and Linux installation/build was not verified. `pip check` only checked the local installed environment, not a clean Linux build.
- Config-var names only: `OTREE_PRODUCTION=1`, `OTREE_AUTH_LEVEL=STUDY`, `OTREE_ADMIN_PASSWORD`, `OTREE_SECRET_KEY`, `DATABASE_URL`. The source generates an ephemeral secret if `OTREE_SECRET_KEY` is absent; hosted deployment must explicitly supply a stable secret and a persistent PostgreSQL URL. The installed oTree falls back to local SQLite if DATABASE_URL is absent, so operations must independently verify it is present and PostgreSQL before startup. The application does not enforce these deployment preconditions. See [oTree admin](https://otree.readthedocs.io/en/latest/admin.html); settle admin credentials before initializing a new database and never reset an existing database to rotate credentials.
- Fonts, OFL notices and logo are local; no third-party tracking/CDN calls were found in project HTML, CSS and JavaScript. SSE branding authorization remains unverified. Confirm privacy, institution and hosting approvals before actual participant use.

Heroku's GitHub integration supports manual deployment and optional automatic deployment; leave the latter disabled. See [GitHub integration](https://devcenter.heroku.com/articles/github-integration) and [codebase preparation](https://devcenter.heroku.com/articles/preparing-a-codebase-for-heroku-deployment). Official docs may contain stale free-tier guidance; check current prices and service terms rather than assuming a free plan. The existing Live Guard and synthetic-only restrictions remain in force.
