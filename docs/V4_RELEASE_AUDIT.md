## Verification

- Release-source suite: 145 passed and 19 historical-fixture tests skipped; the same original suite with the separately retained historical test fixtures in an isolated harness passed all 164. Neither fixture set nor browser data is in this package. The Chrome V3.3.1 acceptance run reported 108 checks and 20 screenshots on a disposable copy; browser process cleanup and SQLite integrity/foreign-key checks passed. Physical Safari and VoiceOver were not tested.
- Eligibility, under-18 and consent exits, cookie choices, delayed native participant reference and copy fallback, four-app order, household validation and after-tax SEK conversion were exercised. Live session creation remains blocked. The Pilot is explicitly labelled synthetic; it must not be repurposed for friends' identifiable or genuine responses without separate design and governance work.
- Fifty concurrent synthetic entrants produced 25 A and 25 B allocations, 50 distinct indices, correct blocks, profiles, treatment mix, and persistent assignments. The test includes repeated simultaneous first GETs, sequential stale duplicate POST, partial dropout and forced server restart. It does not establish the behavior of simultaneous conflicting choice POSTs on PostgreSQL.
- First task display sets a persisted UTC Unix wall-clock start; successful submission records end and elapsed floating-point seconds. A refresh and stale sequential request preserve stored data. A missing start or reversed clock yields an empty duration with a status, not a fabricated zero. Consequently valid timestamps for every real submission depend on production clock behavior and need monitoring. A 2-choice dropout retained its completed tasks; unanswered tasks lacked completion times. Only existing housing task timers were examined; `timing.py` was not changed.
- Untouched attitude submission is rejected; an explicitly selected Neutral is 0 while other values stay unanswered; five distinct values map to Q1–Q5; invalid and duplicate values fail server validation without partial persistence, retaining correctable form values. Historical V3.0 DK meaning was exercised in the external harness. Chrome emulation is not device certification.
- A fresh browser export contained 11 participant rows and 44 unique task keys; 30 completed task timers passed elapsed/nonnegative checks. All three timing columns were compared from native to tasks, long, difference and merged outputs; 44 difference rows remained 44 merged rows. Long completed tasks had exactly one chosen alternative. Native and derived adapters, merge cardinality, historical DK, missing versus zero, A−B orientation and corruption rejection are covered by the regression suite. Unassigned/excluded participants have blank placeholder task rows; they are not fabricated completed tasks.

## Remaining blockers

The declared production requirements lack a PostgreSQL driver. No isolated PostgreSQL server or Heroku CLI was available; real PostgreSQL transactions, Linux build, Heroku resources and hosted behavior are unverified. The browser test server log reproduced two `closing handshake failed / OSError: Socket is not connected` warnings. That same run completed the browser checks and exported responses; its SQLite integrity and foreign-key checks passed. This observation does not establish safety for every network failure or for PostgreSQL. Before any hosted pilot resolve the PostgreSQL/driver work, production secrets and privacy/branding authorization described in the readiness and deployment documents. Existing privacy documents contain historical descriptions; current source and this report take precedence.
